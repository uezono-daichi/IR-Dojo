シナリオの均衡を**実測**する。読んで判断しない。走らせて判断する。

## 最初にやること

```
.venv/bin/python tools/balance.py --json
```

これが SPEC 8.3 のチェックリストを数値で回す。落ちた項目が出発点になる。

## 測定の原則

**数字を動かしたくて測定側を緩めない。** これが一番やりがちな失敗である。
プレイ像（`tools/balance.py` の `Profile`）を足したり直したりしていいのは、
**実在の学習者がそう振る舞うと言えるとき**だけで、
「こうすれば連絡アクションが得に見える」は理由にならない。

過去に実際に踏んだ罠を2つ挙げる。同じことをしないこと。

- **学習者に見えない情報で降りる像を作った。** プレイ中に損失は告げないので
  （CLAUDE.md）、「証拠が奪われてもう解けない」は学習者には見えていない。
  それを打ち切り条件にしたら「奪われた方が早く降りられて得」という
  偽の均衡が出た（-7点の逆転）。**像が使っていい情報は、画面に出ているものだけ。**
- **全アクションを押し切る像しか無かった。** 実在の学習者は完全性ではなく
  予算で降りる。押し切る像だけを見ていると「遅いうえに取りこぼす」という
  一番ありふれた失敗が測れない。

## 見るところ

`tools/balance.py` が出す判定に加えて、必要なら自分で測る。

- **折れ点**（`damage.acceleration.threshold_minutes`）は誰に踏まれるか。
  巧いプレイの 1.1〜1.3 倍が狙い。全アクション合計を基準にすると誰も踏まない
- **網羅と巧いプレイの差**が10点以上あるか。無いなら排他か連鎖が足りない
- **各アクションは一度でも押す価値があるか。** どのプレイ像・どの方針でも
  マイナスにしかならない手は、存在しないのと同じかそれ以下（迷わせるだけ）
- **各出来事は誰に当たるか。** 巧いプレイに当たるなら罰であって教材ではない
- **方針を差し替えたときの開き。** 開かないなら方針が設計されていない
- **critical 論点が永久に解けなくなる経路**が、網羅した学習者に踏まれていないか

## 出すもの

数字と、その数字が SPEC のどの原則に反しているか。

```
✗ 連絡が遅いプレイで得になる
  誤導を追う: business_continuity -3 / evidence_preservation +2 / damage_minimization 0
  → SPEC 5.6.1「連絡が、遅いプレイで実際に得になる（3点以上）」を満たさない
  → 効いていない理由: evidence_preserved は証拠19件で割られるので、2件守っても
     指標は 0.105 しか動かない。重み 0.45 でも総合 1.4点で、払った時間の被害増に負ける
```

**直し方は書かない。** それは design-proposer の仕事で、
測った側が案まで出すと、自分の案に都合よく測るようになる。

原因の分析（なぜその数字になるか）はここで書く。案（どう変えるか）は書かない。
