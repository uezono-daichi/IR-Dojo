見つかった問題に対して**具体的な設計変更案**を出す。実装はしない。

## 案の前に、原因を疑う

**症状に対処する案は、たいてい間違っている。** 過去の例:

- 「取る必要のない情報」を足して網羅を罰しようとした
  → 実務でやるべき初動調査（聞き取り・EDR スキャン・バックアップ確認）を
     罠にしていた。SPEC 6.6 違反。正しい直し方は
     **何も返さないのをやめてネガティブ所見を返す**ことだった
- 単調さに対して演出を足した
  → 盤面を変えない出来事はノイズになった。正しい直し方は
     **出来事に歯を付ける**（奪う／費用の変化を告げる）ことだった
- 折れ点が誰にも踏まれないので演出で補おうとした
  → 原因は SPEC 8.2 の折れ点の置き方の指示そのものが間違っていた

**まず「この設計はそもそも何を教えようとしているか」に戻る。**

## 案が満たすこと

1. **答えを漏らさない**（CLAUDE.md）。案が「学習者に教える」形なら、
   教えるのが結論ではなく資料・手段・規則であること
2. **網羅を罰しない**（SPEC 6.6）。全部押した学習者から事実を奪う案は却下
3. **盤面を変える**（SPEC 5.10）。演出だけの案は却下
4. **方針で評価が変わる**（原則3）。新しい手なら、
   どの方針で正解になりどの方針で違反になるかを必ず決める
5. **画面に足すなら、何かを減らす**。情報を足し続けると初見が読めなくなる

## 効果は見積もる

「面白くなるはず」では通らない。**どのプレイ像の・どの方針で・何点動くか**を、
`tools/balance.py` の枠組みで見積もる。見積もれない案は、
見積もれる形に分解できないか考える。

費用の付け方には型がある。

| 付け方 | 効き方 | 注意 |
|---|---|---|
| 時間 | 全方針に一様。被害を通して効く | **希釈に負けやすい。** `evidence_preserved` は証拠総数で割られるので、19件中2件を守っても総合 1.4点にしかならない |
| 方針の制約 | 方針ごとに正反対にできる | 一番強い。「同じ手が正解にも違反にもなる」を作れる |
| 排他（`destroys`） | 順序が判断になる | critical 論点の唯一の解決手段を奪うなら巧いプレイの遥か後ろ |
| 連鎖（`requires_evidence`） | 網羅の入口を狭める | 1本道にすると踏み外して詰む |

## 出すもの

案を**効果の大きい順**に並べ、それぞれに:

```
## 連絡アクションが割に合わない

現状: 遅いプレイでも最大 +2点。どの方針でも押す理由が無い
原因: evidence_preserved が証拠19件で割られるので、守れる2件では指標が 0.105 しか動かない

案A（推す）: 業務継続最優先の forbid_action に加えて、証拠保全最優先の
  require_before に「周知が先」を足す。証拠保全の下では**出さないことが違反**になり、
  同じ手が方針で正反対の意味を持つ（原則3）
  見積もり: 証拠保全 +4〜5点（違反1件ぶん）、業務継続 -3点（現状維持）
  риск: 証拠保全を選ぶと事実上の必須手になり、選択でなくなる可能性

案B: 奪う証拠を増やす
  見積もり: 3件増やして +2点。希釈の分母が大きいので効きが悪い
  却下寄り: narratively 無理が出る（再起動で消えない証拠まで消すことになる）
```

**推す案を1つ明示する。** 並べるだけで選ばないのは、判断を投げているのと同じ。
危ういところ（риск）も書く。書かない案は採用されない。
