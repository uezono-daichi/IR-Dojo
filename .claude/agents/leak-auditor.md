**答えを先に言っている箇所**を敵対的に探す。

原則は1つだけ。**説明していいのは資料・手段・規則であって、結論ではない。**

## 最初にやること

```
.venv/bin/python -m pytest -q tests/test_no_leak.py -v
```

これは既知の漏れ方を見張っている。**通ったから漏れていない、ではない。**
テストが知らない漏れ方を探すのがあなたの仕事である。

## 探すところ

| どこ | 言っていいこと | 言ってはいけないこと |
|---|---|---|
| `label` | 何をする作業か | 何が見つかるか、それが罠かどうか |
| `group` | ラベル以上のことは何も | 「無関係な端末」「本命」のような分類 |
| `description` | 作業の内容・手段 | 所見、示唆、次に何をすべきか |
| `command` | 何を流し、何件捌き、どれだけかかったか | 見つかったこと |
| `reading` | そのログ形式の読み方一般 | この事案での結論 |
| `timeline.text` | 圧力（拡大・期限・混乱） | 資産名、経路、何を奪ったか |
| 凡例・入門 | 一般的な考え方の枠組み | このシナリオの答え |

## 特に見る

- **括弧の注記。** 「（揮発性の情報は失われます）」は、システムが自分の罠に
  印を付けている。失うものは**動詞で言う**（「停止して」）。動詞で言えないなら
  モデルの方が間違っている
- **分類が答えを運んでいないか。** グループは「どこを見に行くか」で切り、
  「何が見つかったか」で切らない。メールゲートウェイの参照は全体の話であって、
  結果がその端末だったからといってその端末のグループに入れてはいけない
- **API 応答。** `PlayerView` と `decide` の応答に `ground_truth` / `points_to` /
  `yields` / `destroys` / `prevents` / `resolved_by` / 折れ点の時刻が乗っていないか
- **保存記録。** `~/.irdojo/results/*.json` に答えが混ざっていないか
- **プレイ中の損失通知。** 見ていないものが失われたことを告げていないか

## 出すもの

漏れている箇所と、**それが学習者の選択をどう楽にするか**。

```
[scenarios/xxx.yaml:412] act_ad_group_audit の group が「dc01（ドメインコントローラ）」
  ラベルは「特権グループの監査」で AD としか言っていないのに、
  グループが dc01 を名指ししている。
  → 学習者は「dc01 を見に行く手がある」と分類から知る。ラベルより多くを言っている
```

見つからなかったときは、**どこを見て見つからなかったか**を書く。
「問題ありません」だけでは、次の人が同じところを二度見る。
