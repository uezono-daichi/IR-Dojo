# IR Dojo

**自動採点しながら、対応の正解を一つに定めないインシデント対応演習エンジン。**

この2つは、これまで両立しないとされてきた。テーブルトップ演習は
「正解を一つに定めない」を採点の放棄によって達成し、
自動採点するもの（分岐ナラティブ、Cyber Range、エージェント評価ベンチマーク）は
自動化の代償にトレードオフを捨てている。

IR Dojo は**対応方針を採点の入力にする**ことで両立させる。
方針を固定すれば答えの鍵が定まって自動採点が成立し、
方針を差し替えれば鍵も変わるので単一の正解が存在しない。
**同じシナリオが、方針の数だけ違う正解を持つ。**

> **CSS2026 MWS Cup ハッカソン提出作品** ／ チーム **YokoGlitch**
> 提出時点のコード: [`v0.2`](../../tree/v0.2)
> プレゼン資料と紹介動画は提出フォームから出しています（**このリポジトリには置きません** —
> 置き場が2つあると、どちらが正か分からなくなるため）。

# 遊んでみる方へ

## まず — コードもドキュメントも、遊ぶ前に読まないでください

**このリポジトリには答えが書いてあります。** 演習は「何が侵害されているか」を
自分で見抜くものなので、先に読むと成立しません。

| 場所 | 何が書いてあるか |
|---|---|
| `scenarios/` | **真相そのもの**（どれが侵害され、どれが偽の手がかりか） |
| `SPEC.md` | 設計の議論。同梱シナリオの真相を 400箇所以上で名指ししている |
| `tests/` | 期待値として**答えが直に書いてある**行がある |
| `tools/` `irdojo/` `docs/` | コメントと例に真相が出る |
| `git log` / コミットの中身 | 上のすべてが履歴に残っている |

**読んでよいのは、この README と、ブラウザに出る画面だけ**だと思ってください。
（うっかり開いてしまっても大丈夫です。その演習だけ飛ばして、別のを遊んでください。
5本入っています。）

## 1. 動かす

必要なのは **Python 3.11 以降**だけです（`python3 --version` で確認できます。
入っていなければ <https://www.python.org/downloads/>）。

**ターミナルを使いたくない方へ。** リポジトリを
[zip でダウンロード](../../archive/refs/heads/main.zip)して展開し、
中の **`start.command`（Mac）** か **`start.bat`（Windows）** をダブルクリック
してください。初回だけ1〜2分かかって、あとはブラウザが開きます。

Mac で「開発元を確認できないため開けません」と出たら、
そのファイルを**右クリック →「開く」**でもう一度試してください。

---

以下はターミナルを使う場合です。

```
git clone <このリポジトリの URL>
cd IR_Dojo
python3 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/python -m irdojo
```

Windows は最後の2行だけ違います。

```
.venv\Scripts\pip install -e .
.venv\Scripts\python -m irdojo
```

ブラウザで <http://127.0.0.1:8000> が開きます。
**あなたの機械の中だけで動きます。** どこにも送信していません。

終わるときは、ターミナルで `Ctrl+C`。
2回目以降は最後の1行（`python -m irdojo`）だけで起動します。

## 2. 遊ぶ

**インシデント対応が初めてなら、「はじめる」を押したあとの「はじめて学ぶ」から。**
インシデントとは何か、備えとは何か、起きると何が失われるか、記録をどう読むかを
**12章**の座学にまとめてあります（全部読んでも25分ほど）。
6つの章には「読んだら試す」が付いていて、その場で対応する演習に飛べます。

そのあとが練習です。一覧の先頭に `練習` の印が付いた2本があります。

| | 何を覚えるか | 目安 |
|---|---|---|
| 遊び方を覚える | 画面の読み方と、3つの手順 | 5分 |
| はじめてのインシデント対応 | 何をどう考えるか。**インシデント対応が初めてでも大丈夫です** | 15分 |

どちらも画面の左に案内が出て、そのとおりに進めば最後まで行けます。

そのあとが本番の5本です。**1本 10分くらい**で、どれからでも構いません。

お願いが4つあります。

- **調べてから決めてください。** 分からないまま決めても進みます（それも測っています）
- **途中で人に聞かないでください。** 分からなかった場所そのものが知りたいことです
- **終わったら講評まで読んでください。** そこで初めて答えが出ます
- 余裕があれば、**同じ演習をもう一度、別の「対応方針」で**やってみてください。
  ここがこの道具の中心です

途中でやめても構いません。**やめた場所を覚えておいてください。**

## 3. 気づいたことを Issue に書いてください

**感想ではなく、やったことを書いてもらえると、いちばん役に立ちます。**

1. **最後に押した手を、なぜ押したか**
2. **方針を変えたとき、何を変えたか**（2周目をやった方だけ）
3. **意味が分からなかった画面はどこか** — 場所だけで構いません

「面白かった／難しかった」は無理に言語化しなくて結構です。
**どこで手が止まったかは、記録のほうに出ています。**

盤面の答えに触れる話は、Issue の本文を
`<details>` で畳んでもらえると助かります（他の人のネタバレになるため）。

## 4. 記録はあなたの機械の中だけに残ります

遊ぶと結果が自動で保存されます。**送信は一切しません**（[SECURITY.md](SECURITY.md)）。

| | 場所 |
|---|---|
| Mac / Linux | `~/.irdojo/results/` |
| Windows | `C:\Users\<あなた>\.irdojo\results\` |

中身は点数・押した手の順番・かかった時間だけで、**答えは入っていません。**
不具合の報告に添えると原因が特定しやすくなりますが、**任意**です。
消すときはフォルダごと削除して構いません。

## 困ったら

- 画面が真っ白 → ブラウザを再読み込み（Mac: ⌘R / Windows: Ctrl+R）
- 「サーバに接続できません」 → ターミナルで `python -m irdojo` が動いているか確認
- `pip install` で止まる → Python が 3.11 以上か確認（`python3 --version`）
- それでも動かない → [Issue](../../issues) に、OS・Python のバージョン・
  ターミナルに出た文言を貼ってください

# 開発する方へ

## 動かす

```
git clone <this repo>
cd IR_Dojo
python -m venv .venv && . .venv/bin/activate
pip install -e .
python -m irdojo
```

ブラウザで <http://127.0.0.1:8000> が開く。
サーバは `127.0.0.1` に固定してバインドする（[SECURITY.md](SECURITY.md)）。

開発・テスト用の CLI もある。**人に見せる想定はしない** —
被害が膨らむ緊張感も、未解消論点を抱えた決断の感覚も、テキストでは伝わらない。

```
python -m irdojo --cli --list
python -m irdojo --cli ransomware-initial-response-01 --policy damage_minimization --assist hard
```

## 何を測るか

採点は3層に分かれる。

| 層 | 内容 | 方針依存 | 採点 |
|---|---|---|---|
| **事実認識** | 被疑判定の精度、誤導耐性、未解消論点 | しない | する（重み 0.7） |
| **方針適合** | 与えられた方針の重みと制約への整合 | する | する（重み 0.3） |
| **帰結** | 経過時間・被害額・業務影響・証拠保全 | — | **しない**（生値で提示） |

帰結を直接採点しないのが要である。被害額を採点すると
「早く封じ込めるのが正しい」という規範を暗に押し付けることになる。

測ろうとしているのは、実務で見落としが生じる2つの経路である。

1. **偽の根拠に依拠した** — もっともらしいが無関係な事象を攻撃の痕跡だと誤認する
2. **根拠の不足を認識しなかった** — 説明できていない事象が残っているのに全容が見えたと判断する

そのために、**被疑判定（何が侵害されていると判断したか）と
封じ込め行動（何を止めるか）を分離**している。前者は事実として正誤が定まり、
後者は方針次第で変わる。分けることで前者だけを純粋に採点できる。

## 何を作らないか

- **実環境ではない。** 仮想サーバもログファイルも立てない。ただし証拠の中身は本物のログ断片を使う
- **最適解を教えない。** 最短経路は disclaimer 付きの参照値に留め、
  主役は誤導の棄却経路と未解消論点の含意（推論の穴の指摘）に置く
- **その場で正解を教えない。** 制約違反も誤導フラグも被害曲線の折れ点も、講評で初めて開示する

## アシストレベル

同じシナリオを3段階のアシストで解ける。

| レベル | 論点の扱い | 測っているもの |
|---|---|---|
| `assisted` | 一覧と解消状態を常時表示 | 未解消と**知りながら**決断したか |
| `standard` | 一覧は出すが解消状態は出さない | 自分が何を解消できたか**把握**できるか |
| `hard` | 一切表示しない。証拠の要約も出ない | 未解消があること自体に**気づける**か |

**採点式はどのレベルでも同一である。** アシストは表示の設定であって採点の設定ではない。
したがってレベルをまたいだスコア比較に意味がある —
その差がそのまま「アシストにどれだけ依存していたか」を表す。

## シナリオを書く

```
scenarios/<id>.yaml
```

YAML を1つ置くだけで増える。Python は1行も触らない。
書き方は [docs/scenario-authoring.md](docs/scenario-authoring.md)、
DSL の全項目は [SPEC.md](SPEC.md) の Part 5 を参照。

同梱は**練習2本＋本番5本**。本番の5本は**系統を変えてある** — どれも「早く止めるほど良い」では解けない。

| id | 題材 | 判断の形 |
|---|---|---|
| `ransomware-initial-response-01` | 深夜のファイルサーバ異常 | 記録を消すのは**自分の手**。誤導は時刻の近さ |
| `oauth-consent-abuse-01` | SaaS テナントの不正同意 | 記録を消すのは**時計**（保持期間）。誤導は権限の広さ |
| `software-distribution-spread-01` | 配られていく更新 | **盤面が動く**（調べている間も配られ続ける）。誤導は共通原因 |
| `ot-line-logic-tamper-01` | 止めるか、動かし続けるか | **止めること自体が危険側**になりうる（産業制御）。方針に安全と生産が並ぶ |
| `insider-exfil-suspicion-01` | 最終出社まで十日 | 技術的な封じ込めが**人事・法務の手続きと衝突する**。方針に立証可能性が並ぶ |

**練習の盤面が2本ある**（`tutorial-01-how-to-play` / `tutorial-02-first-response`）。
案内が付き、一覧では先頭に並ぶ。**盤面としては本物で**、誤導も critical 論点もあり、
ローダの検査も全シナリオ検査も全部通っている — 偽の盤面で操作だけ覚えても、
本番で同じ画面に見えないため。設計の均衡（`balance.py` と入口の 3×3）からは外れる。
書き方は SPEC 3.13。

**2本目は幅を足すためだけのものではない。** DSL が1本目の世界を
前提にしていた箇所（業務停止と揮発性の消失を同一視していた条件、
依存が木である前提、束の検査が資産 id しか見ていなかったこと）は、
2本目を書いて初めて表に出た。経緯は SPEC 8.6。

**3本目は真実そのものを動かす。** 1本目・2本目の `ground_truth` は執筆時に
固定で、`timeline` は圧力を運ぶだけだった。配布の仕組みを攻撃者が握っていると、
調べている間も配られ続ける — `ground_truth.spreads`（SPEC 5.2）が
侵害資産を増やし、再現率と封じ込めの完全度の**分母が動く**。
採点がどの時点の盤面と突き合わせるかは、そこで初めて意味を持つ。

**4本目・5本目は、封じ込めの向きを折る。** 1〜3本目は方針が違っても
「どれだけ急いで止めるか」の1軸に収まっていた。産業制御では止める手が
安全の側に副作用を持ち、内部不正では先にアカウントを止めることが
立証可能性を壊す側に回る。**早期封じ込めが全方針の共通解でなくなる。**

複雑度（★1〜5）は**作者が書かない。** 誤導証拠の数と plausibility、
critical 論点の数、証拠数からローダが算出する。
作者の主観で付けるとシナリオ間で一貫しないため。

**この数字は画面に出していない。** 同梱5本は raw 8.86〜9.92 で全部★3に落ちる。
式が壊れているのではなく、執筆ガイドが薦める規模（誤導2〜3・critical論点2〜3）が
その定義域のほぼ一点だからで、**ガイドに従って書けば★3になる。**
定数は絞り込みに使えないので、作者向けの計器として `tools/balance.py` に残した。
演習を選ぶ画面の札に出るのは、代わりに**その演習が持つ方針3つの名前**である
（どの綱引きを練習するのかは、そこに出ている）。SPEC 3.12 / 7.6.20。

## 開発

```
pip install -e ".[dev]"
pytest                                   # 580本（569 通過・11 skip）
```

- `tests/test_scoring.py` — SPEC 6.8 の計算例をそのまま検証する
- `tests/test_edge_cases.py` — SPEC 6.7 の端値とローダが拒否すべき構造
- `tests/test_no_leak.py` — プレイ中の全レスポンスを走査して答えの漏洩を検査する

### 設計を測る

**「面白くない」「分かりにくい」は感想ではなく測る対象**にしている。

```
python tools/balance.py                  # 設計の均衡（SPEC 8.3 のチェックリスト）
python tools/balance.py <シナリオID>     # 同梱のどれでも
python tools/balance.py --json           # 機械可読（落ちた項目があれば終了コード 1）
npm install
node tools/playtest.mjs --dpr 2 --scenario <シナリオID>   # 実際に遊ぶ＋スクショ
python tools/playtest_report.py                          # 人に遊んでもらった記録を読む
python tools/make_tester_zip.py                          # テスト配布用の zip を作る
node tools/playtest.mjs --dpr 2 --assist hard            # hard は画面の作りが一番変わる
```

`tools/balance.py` はプレイ像（巧い / 止めるだけ / 全部押す / 誤導を追う /
誤導を棄却する / 調べずに止める / 根元を落とす / 空振りで見切る /
見切らずに戻る）ごとに、**宣言と封じ込めまで**実際に
遊ばせる。折れ点は誰かに
踏まれるか、網羅は損になっているか、誤導に乗ると実際に点が下がるか、
**名指ししなかった失敗が名指ししすぎた失敗と同格に高くつくか**、
何もしないプレイが調べたプレイに勝っていないか、方針を差し替えると評価が
変わるか、を数字で判定する。

プレイ像が使ってよいのは**画面に出ているものだけ**である。被疑判定は
`ground_truth` からではなく、ブリーフィングと取得済み証拠から組み立てる
（`tests/test_balance_instrument.py` が見張っている）。

`tools/playtest.mjs` は実際にブラウザで遊び、描画エラー・横はみ出し・
canvas の暴走・アクションの画面外への押し出しを拾ってスクリーンショットを撮る。
**canvas を含む画面は dpr 2 でも必ず確認する** — dpr 1 だけの検証は
Retina で必ず起きる不具合を素通りさせる（SPEC 7.6.9）。
`--assist hard` も通す — グラフも論点も資産盤も出ないので、
他のレベルで整っていても hard だけ崩れることがある。

`CLAUDE.md` に守るべきことがある（答えを漏らさない / 網羅を罰しない /
